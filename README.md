# 💰 Мои финансы — учебный проект React + TypeScript

Мини-сайт: трекер личных доходов и расходов. Ты добавляешь операции,
видишь баланс, сумму доходов и расходов, можешь удалять и фильтровать записи,
а данные сохраняются между перезагрузками страницы.

Это **учебный** проект. Идею и каркас подготовил твой куратор (Claude),
а весь React-код по этапам пишешь **ты**. Я рядом — объясняю, подсказываю
и проверяю. Подробнее о правилах работы — в `CLAUDE.md`.

---

## 🚀 Как запустить

```bash
npm install      # один раз — поставить зависимости
npm run dev      # запустить дев-сервер (откроется http://localhost:5173)
```

Полезные команды:

```bash
npm run build    # сборка + проверка типов TypeScript
npm run lint     # проверка кода линтером
```

Сервер с горячей перезагрузкой (HMR): меняешь файл — браузер обновляется сам.

## 🎯 Задание по этапам

Делаем по одному этапу. Закончил этап — скажи мне, я проверю и дам обратную связь,
прежде чем идти дальше. Не торопись: цель — понять, а не просто получить рабочий код.

### Этап 1. Вывод списка операций
**Что нового:** компоненты, пропсы, `map`, ключи `key`, типизация пропсов.

- В `App.tsx` выведи все операции из `sampleTransactions`.
- Создай компонент `TransactionList` (файл `src/components/TransactionList.tsx`),
  который принимает проп `transactions: Transaction[]` и рендерит `<ul class="transaction-list">`
  со списком `TransactionItem` (его я уже написал — бери за образец).
- Каждому элементу списка нужен уникальный `key` (подсказка: `transaction.id`).

✅ **Готово, когда:** на странице видно 5 операций, доходы зелёные, расходы красные,
а в консоли браузера нет предупреждения про `key`.

---

### Этап 2. Форма добавления операции
**Что нового:** `useState`, контролируемые поля, типы событий, обновление состояния иммутабельно.

- Перенеси список операций в состояние: `const [transactions, setTransactions] = useState<Transaction[]>(sampleTransactions)`.
- Создай компонент `TransactionForm` с полями: название (`input`), сумма (`input type="number"`),
  тип (`select` с `income` / `expense`). Используй класс `form`.
- При отправке формы создавай новый объект `Transaction` и добавляй его в список.
  Подсказки: `id` — `crypto.randomUUID()`, дата — `new Date().toISOString()`.
- Форма общается с `App` через колбэк-проп, напр. `onAdd: (t: Transaction) => void`.

✅ **Готово, когда:** заполняешь форму, жмёшь «Добавить» — новая операция появляется
в списке, а поля очищаются. Страница при отправке **не перезагружается**
(не забудь `e.preventDefault()`).

---

### Этап 3. Сводка: баланс, доходы, расходы
**Что нового:** производные значения, `reduce`, вынос логики из разметки.

- Создай компонент `Summary`, который принимает `transactions` и показывает три карточки
  (`summary__card`): «Доходы», «Расходы», «Баланс».
- Посчитай суммы через `reduce`. Баланс = доходы − расходы.
- Эти значения **не храним в состоянии** — они вычисляются из списка при каждом рендере.

✅ **Готово, когда:** при добавлении операции цифры в сводке пересчитываются сами.

---

### Этап 4. Удаление и фильтр
**Что нового:** передача колбэков вниз, `filter`, условный рендеринг, состояние-переключатель.

- Добавь в `TransactionItem` кнопку удаления (класс `transaction__delete`, например «×»)
  и проп `onDelete: (id: string) => void`.
- Реализуй удаление в `App` через `setTransactions(prev => prev.filter(...))`.
- Добавь фильтр (`all` / `income` / `expense`) — блок с классом `filter`,
  активной кнопке давай класс `is-active`.
- Если после фильтра список пуст — покажи заглушку с классом `empty`.

✅ **Готово, когда:** можно удалять операции и переключать фильтр; сводка считает по всем
операциям, а список показывает отфильтрованные.

---

### Этап 5. Сохранение в localStorage
**Что нового:** `useEffect`, побочные эффекты, сериализация JSON, ленивая инициализация состояния.

- Сохраняй `transactions` в `localStorage` при каждом изменении (`useEffect` с зависимостью).
- При старте читай данные из `localStorage` (ленивый инициализатор `useState`).

✅ **Готово, когда:** добавил операции, перезагрузил страницу — они на месте.

---

### Этап 6 (бонус). Полировка
Выбери, что интересно: категории операций, форматирование дат, валидация формы
(не пускать пустое название / сумму ≤ 0), пустое состояние с подсказкой,
или простая диаграмма доходов/расходов. Обсудим, что взять.
